### A0 · ★ 修正「布局收敛闭环」既有错误(最高优先,先于其他新增)

**现状(实测)**:`.claude/rules/godot-mcp-ui.md:103` 起 / 模板 `rule-templates.ts:675` 起的「布局收敛闭环」写的是 `ui_build_layout(tree 含 rect)` → `ui_measure_layout(expect_tree)` → 循环 → `ui_build_layout(persist=true)`。第一步未传 persist(默认 false,`ui-layout.ts:708`)——而 measure 是**独立 Godot 进程**从磁盘 `_mcp_load_scene` 加载(`ui-measure.ts:60`),persist=false 时刚建的运行时树随进程退出已丢,measure 读到的是旧场景 → diff 错位或 `actual:null`。该缺陷 **2026-08-16 审查已记录**(`D:\GitHub\godot-mcp-series\godot-mcp-enhanced\docs\reviews\2026-08-16-prototype-import-spec.md` B-1 条)但规则文本至今未修。仓库集成测试注释同样写明「build 是运行时节点(进程退出即丢),测量须同进程」(`test/integration/ui-layout-integration.test.ts:111`)。

**改法(双副本同段重写)**:

```markdown
### 布局收敛闭环(v2)

ui_build_layout(tree 含 rect, **persist=true 写盘**) → ui_measure_layout(expect_tree=同一棵 tree 含 rect,**不带 node_path**) → 按 data.layout_verify.diff 的 Δ 数值修 tree → 重新 ui_build_layout(persist=true) → 循环至全绿。
- 每一轮验证循环都以 persist=true 落盘为默认——measure 是独立进程,从磁盘加载场景;persist=false 的运行时树测不到(进程退出即丢)。
- 不想污染目标场景时:先把 scene_path 指向临时场景路径(如 res://tmp/ui_verify.tscn)
  走完循环,全绿后把 scene_path 换成目标场景再 build 一次 persist=true(persist 写盘
  为 pack → tmp → rename 覆盖写)。**前置:临时场景文件与所在目录须先存在**——build
  脚本首行 `_mcp_load_scene` 对不存在的场景直接 "Failed to load scene" 退出,persist
  无从执行;先用 scene 工具创建空场景(或复制目标场景)再进循环。
```

(坐标系语义/layout_verify 结构等既有正确内容保留不动;`ui_measure_layout` 单独使用段保留。)

**配套测试(防规则再漂移)**:新增 1 条文档流程集成测试——`ui_build_layout(persist=true)` 写盘 → 独立 `ui_measure_layout(expect_tree=同树含 rect)` → 断言 diff 全绿非空。把规则声称的闭环用测试钉死。

**验收消账(有判定力的正向断言)**:`grep` 双副本确认 ① 新骨架字样「每一轮验证循环都以 persist=true」命中;② 旧闭环首句形态「`ui_build_layout(tree 含 rect)` → `ui_measure_layout`」零命中(现状文本含此字样,改动后应消失——反向断言对现状非恒真,才能区分"已改"与"漏改")。「persist 默认 false」作为运行态语义的事实描述允许保留,但不得与验证闭环挂钩。

**内容骨架 v2**(clip_contents 归 A3 不在此重复;验证流程归 A0 只引用):

```markdown
## 跨引擎迁移 UI 构建策略(从 Unity/Cocos/Egret/Web 等迁移时必读)

### 1. 整体性判定:视觉组必须容器化(治"拆散"与"内容超出背景框")
源引擎 UI 多为绝对坐标平铺。迁移时先做视觉组识别:一个背景 + 其内文案/图标/交互件
(卡片、面板、按钮、条目),必须重构为容器子树,禁止平铺成兄弟节点 + 手动 rect 还原。
**按构建路径选容器方案**:
- **ui_build_layout / 手写 tscn(容器布局子节点)**:背景自适应首选 `PanelContainer`
  ——它本身是 Container,尺寸随子内容最小尺寸自动撑开,背景=内容边界。多向排布用
  `PanelContainer > MarginContainer > VBox/HBox`。注意:`Panel` 继承 Control **不是**
  Container,不会被子节点最小尺寸撑开——放进 VBox 拿到的是自身最小尺寸(常为 0),
  子内容照样溢出;要 Panel 视觉样式又想自适应,外包一层 PanelContainer。
- **ui_import_prototype(绝对 rect 子节点)**:背景仍用 `Panel`(翻译器样式槽位仅映射
  Panel/ProgressBar/Button/Label,PanelContainer 的 bg/border 会触发
  "无该控件的样式槽位,已忽略" warning);容器排布靠原型 `flow` 字段;**绝对 rect
  子节点永远不要放在 Container 父下**(rect/anchors 会被容器重排覆盖,见「扁平列表,视口绝对坐标」rect 求解段)。
- 同款条目重复出现 → 建成独立场景(组合控件)再 instance,不做兄弟复制。
- 固定 size 的 Panel 仅用于纯装饰层(无动态内容);有内容的一律走容器自适应。

### 2. 对齐三原则(治"对齐乱")
- 容器内对齐 → 交给 `size_flags`(SIZE_FILL/SIZE_EXPAND 搭配 SIZE_SHRINK_CENTER/
  SIZE_SHRINK_END 预设)+ Box 容器的 `alignment`
- 跨控件对齐 → 交给共同父容器(把要对齐的控件放进同一个 Box/Flow)
- 绝对坐标/锚点定位 → 仅限 overlay、特效层、全屏装饰;禁止逐控件手算 x/y 模拟对齐
  (字体行盒差异会让手算必错,见下条)
- **嵌套圆角**:外层圆角 = 内层圆角 + 内边距(Concentric Radius)才视觉协调;padding
  大时视为分离表面不强套公式。**光学对齐**:图标/三角形等非对称图形几何居中后需
  1~2px 级偏移修正;文本行盒与字形 ink 高度差异致跨引擎"文字不居中",第一步诊断用
  `game_query get_font_report`(ink_center_shift 字段;**需 bridge、游戏运行中**——
  构建期无游戏时先用 `ui_measure_layout` 量行盒尺寸做粗判,精确诊断留到运行期)——换字体可能缩小偏差但不改变
  行盒居中算法,先看诊断再决定。
```

### A3 · engine-quirks 新增两条引擎行为陷阱(I-6 收窄:设计知识移 A1)

**位置(实测)**:模板 key `'godot-mcp-engine-quirks.md'` 起 `rule-templates.ts:982`;插入 UI/Control 相关条目区(「Label 垂直对齐」等附近)。落盘双副本基线 **11,337** 字符,新增硬上限 **+1.2k 字符(落盘口径)**。

1. **★ StyleBoxFlat 圆角是固定像素半径,不随 Control resize 重算**(治症状①):控件被拉伸时半径不变、比例失真;非等比 `scale` 更会让圆角变椭圆。变通:① 容器自适应避免拉伸(A1 策略) ② 四角独立用 `corner_radius_top_left` 等属性 ③ 需随尺寸等比缩放的圆角背景改 `StyleBoxTexture`/`NinePatchRect` 九宫格。
2. **★ Control 默认 `clip_contents=false`,不裁剪子树溢出**:症状②的引擎侧根因之一;解法优先级:容器自适应(首选)> `clip_contents=true`(滚动区/动画溢出场景的兜底;静态布局开 clip 是掩盖布局错误)。

(原 v1 第 3/4 条 Concentric Radius / Optical Alignment 是设计工程知识而非引擎行为,与 engine-quirks「定位」段冲突,移入 A1 对齐段;A2 保留其诊断入口引用。)

## 四、批 B 详解(验证层代码)

### B1 · border 四边各异消静默(B-3 修正:改动面 3 → 7 处)

**现状(实测 `D:\GitHub\godot-mcp-series\godot-mcp-enhanced\src\tools\ui\prototype-import.ts`)**:schema 只收统一 `border: {width, color}`(`:109`);上游 CSS 四边各异时提取脚本取 top 且仅当 `borderTopWidth > 0` 才输出(`rule-templates.ts:772` 附近),信息丢失且无 warning;`style_verify` 期望与实测同源恒绿——且 `ui_pixel_verify` 的采样点按 border+radius 内缩后采背景色、**不采边框本身**(`pixel-verify.ts:64-76`),只能在某边特别厚且采样点恰好落进边框时**间接**暴露,不可依赖。

**改动设计(七处,向后兼容)**:

1. **schema 扩展**(`prototype-import.ts:109` `border: z.strictObject`):新增可选 `perSides?: { top: number; right: number; bottom: number; left: number }`;不传则行为完全不变。
2. **`GeometryNode` 接口**(`prototype-import.ts:36`):`border` 类型同步补 `perSides`(否则翻译器访问 `nd.border.perSides` 无法通过 TS 编译)。
3. **翻译器 warning**:接收到 `perSides` 且四边值不全等时,`build_warnings` 追加 `"border sides differ (top/right/bottom/left = ...); using top — fix source or verify visually"`;仍取 top(渲染行为不变,只消静默)。
4. **top=0 边界专项**:提取脚本现状只在 `borderTopWidth > 0` 时输出 border——「仅下边框/分隔线」(top=0,bottom>0)不进 `perSides` 分支,静默缺口仍在;而若为消静默把 `width:0` 也发出,翻译器「有 border 无 bg」分支会设 `draw_center=false`(`prototype-import.ts:322-324` 静默改透明底逻辑)→ 节点全透明,**是回归**。决策:`perSides` 仅在 top>0 且四边各异时附带;top=0 且其余边>0 时由提取脚本输出独立提示字段(不产 border spec),翻译器对此提示透传成 warning。**该提示字段必须同步列入改动点 1 的 NodeSchema 扩展与改动点 2 的 `GeometryNode` 接口**(如 node 级 `borderNotice?: string`,字段名实现时定)——`NodeSchema` 是 `z.strictObject`(`prototype-import.ts:86`,未知字段拒绝)且 `parseGeometry` 在翻译器之前执行,未声明字段到不了"翻译器透传"那一步,直接 `INVALID_PARAMS`。
5. **规则自认句同步**:`rule-templates.ts:702` 与 `.claude/rules/godot-mcp-ui.md:130` 的「**四边各异不单独 warning**——生产者仅取 top……真暴露渠道是 ui_pixel_verify 像素采样」整句改为新行为描述(warning 已存在;ui_pixel_verify 不采边框本身,只能间接暴露)。
6. **提取脚本示例段更新**(`rule-templates.ts:724-789` 分发文档内 JS 片段):读 `computedStyle` 四边 `borderXxxWidth`,top>0 且四边各异时附 `border.perSides`(`width` 仍取 top 兼容);分发文档同步写明字段语义与 top=0 行为。
7. **文档面**:`src/tools/ui/index.ts:166` `geometry` 参数 description 补 `perSides` 语义 → 重新生成 `docs/tools/ui.md`(`gen:tool-docs`)+ `npm run build-matrix`(description/schema 变更会被 CI 的生成物 diff 门禁拦截,不重生成即红)。

**兼容性说明**:`z.strictObject` 会拒绝未知字段——旧版 server 收到带 `perSides` 的 geometry 会报参数错。规则与 server 同版本分发(目标项目 reconcile 同时更新),实际风险低;在 CHANGELOG 迁移说明写一句。

**测试计划**:

- schema 层:`perSides` 合法/非法(缺边/负值)用例。
- 翻译器层:带 `perSides` 四边各异 → warning 存在且取 top;全等 → 无 warning;不带字段 → 零变化(回归)。
- **top=0 用例**:top=0/bottom>0 → 无 border spec + 透传提示;显式 `width:0` + 无 bg → 不触发 `draw_center=false` 全透明回归(或 schema 层拒绝 width≤0,二选一,实现时定)。
