## 三、差异化对标:unity-mcp-server 可靠性骨架 vs enhanced 现状

unity-mcp-server(AnkleBreaker,93 commits modernization)的核心命题:"多 agent 共享一个 stdio server、多实例并存时,命令绝不能看似成功地落到错误项目"。逐件对照:

| unity-mcp-server 组件 | enhanced 对应现状(实测) | 差距判定 |
|---|---|---|
| 注册表 + 心跳(instance-discovery) | `addons/.../instance_registry.gd`(心跳写 `~/.godot-mcp/instances`,含 godotVersion 字段 `:91`)+ TS 侧 `resolveBridgePort`(`src/core/bridge-client.ts:126`,registry 未命中→secret 窗口扫描 `:206-225`)+ `BRIDGE_REGISTRY_MAX_AGE_MS` 超龄清扫 | ✅ 等价已有 |
| ping 身份校验(bridgeIdentity,不认任意 200 服务) | ping 响应带 `bridgeVersion` + `capabilities`(`mcp_bridge.gd:912-913`),但 TS 侧无"响应缺身份字段即拒绝"的强校验语义 | ⚠️ 部分有,可小补(批次 1 第 2 条) |
| fail-closed 路由(项目消失要求显式重选,绝不回落默认端口) | 实际防线是 **per-port secret 认证**:每个 bridge 实例独立生成 secret(`mcp_bridge_%d.secret`,`mcp_bridge.gd:627`),连错端口必然 auth 失败 → 写命令不会静默落错实例;另有 60s 端口避让(`bridge-client.ts:677`)。但 registry+扫描全未命中时仍**盲回落 9081**(`bridge-client.ts:225`,注释已识别"从无害变连不上"的风险) | ⚠️ 密码学防线强于身份校验(等价 fail-closed),盲回落保留待议 |
| **幂等队列**(requestId 指纹去重 + 按身份重试 + 拿 ticket 后只轮询不重发) | **无**。JSON-RPC `id` 仅用于响应关联(`mcp_bridge.gd:1077` 等);TS 侧超时重试=新 id 重发;GD 侧无去重表 | ❌ **最大差距** |
| **outcomeUnknown 结构化错误**("原请求可能已执行,先检查再重试") | 超时报错文案是"agent 自愈:查游戏报错 / 加大 timeout"(`bridge-client.ts:44` 注释),不区分"未执行"与"已执行但响应丢失" | ❌ 缺失(与幂等配套) |
| 准入 admission(256 未决命令 + 字节记账) | 无 | 低优先(单机单 agent 场景压力小) |
| 响应字节限制(UTF-8 计数 + 恢复标识符保留 + 软限前插警告) | 仅 sync_state 有 256-node cap(`game-bridge.ts:1044-1066`);无通用字节级响应防线 | ⚠️ 中优先 |
| 驱逐即收紧未知 agent 权限(agent-state LRU) | 无 agent 概念(单 agent 为主);观察 profile(player/debug)+ `GODOT_MCP_BRIDGE_ALLOWED_PROFILES` 是近似物 | 低优先,随多 agent 支持再做 |

**判定**:报告"最大竞争压力"的判断成立,但压力集中点与 unity 场景有偏移——enhanced 的 secret 认证已把"落错实例"的写风险挡死(unity 无 per-instance secret 才靠身份校验+fail-closed);真正的空白是**超时歧义下的幂等性**(Godot 卡主线程:编译、场景切换、长 playtest step 都会造成"命令已执行但响应超时",agent 重试即重复执行)。

## 四、落地方案(分批,含验收标准)

### 批次 1:传输卫生机械化 + 小缺口补齐(P1,预计 1-2 天)

目标:把"已覆盖"变成"不会回归",补两个小缺口。

1. **stdout 纪律 ESLint 门禁**:`eslint.config.js` 加 `no-restricted-syntax`(或 overrides 按 server 可达文件列表),禁止 `src/index.ts`、`src/GodotServer.ts`、`src/core/**`、`src/daemon/**`、`src/web-gui/server.ts` 等进程内模块使用 `console.log`(CLI 模块白名单豁免)。验收:故意在 GodotServer.ts 写 console.log → lint 红;现有代码 lint 绿。
2. **ping 身份校验强化**:TS 侧连接后首个 ping 响应若缺 `bridgeVersion`(或新增 `instanceId` 字段)→ 拒绝认作 enhanced bridge,报结构化错误(对齐 unity "unrecognized" 语义,防任意 TCP 服务被当 bridge)。验收:单测 fake 无版本 ping → 拒连。
3. **通用响应字节防线**:ToolDispatcher(或 bridge 响应封装层)加 UTF-8 字节上限(参照 `responseBytes` 语义:序列化后计数;超硬限返回 `response_too_large` + 保留恢复标识符如 instanceId/label;超软限前插 warning 块)。验收:单测覆盖超限截断与恢复标识符保留。
4. **规约入库**(无代码):`src/tools/rule-templates.ts` + `.claude/rules/godot-mcp-engine-quirks.md` 增补一条:"新增 EditorInterface/engine API 调用须确认 4.5-4.7 全版本存在;4.6+ 新 API 必须 has_method 守卫 + `.call()` 字符串形式(parse-safe),或版本分支"——把 yanhuifair v1.12.3 的教训转成开发规约。⚠️ 此项触发规则模板变更硬门禁(须 bump patch 版本 + `STRICT=1 npm run check:rules-sync`)。

### 批次 2:bridge 协议幂等层(P1.5,预计 3-5 天,协议演进)

目标:消除超时歧义下的重复执行。设计要点(对齐 unity queue-transport 语义,按 TCP 单连接场景裁剪):

1. **能力协商**:`mcp_bridge.gd` ping 响应 `capabilities` 数组增加 `"idempotent-v1"`;TS 侧探测,旧 bridge 无此能力自动退回现行为(向后兼容,零破坏)。
2. **请求侧**:TS 每个写类命令(game_write/call_method/custom_command/qa 的 input 类步骤)生成 `requestId`(UUID),带在请求 JSON 里。
3. **GD 侧去重表**:LRU(上限 256 条,TTL 窗口如 120s),`{requestId → 完整响应}`;收到已存在 requestId 直接回缓存响应,不执行命令。
4. **TS 侧超时语义改造**:超时后**不重发**,返回结构化错误 `{ outcomeUnknown: true, requestId, advice: "原命令可能已执行,先 game_query 核实状态再决定是否重试(重试用同一 requestId)" }`——把"加大 timeout"的模糊指引升级为精确语义。
5. **重试规则**:agent 用**同一 requestId** 重试(命中去重表则拿回原结果,未命中则安全执行)——即 unity "按身份重试而非按命令重试"。
6. **测试**:QA 套件 + 单测覆盖——同 requestId 两发命令只执行一次;超时后同 requestId 重试拿缓存;旧 bridge(无 capability)退回现行为。

### 批次 3:内容哈希同步(修法④回流,P1,预计 1-2 天,可与批次 1 并行)

见第二节修法④回流设计(指纹清单生成 + ping 回传比对 + doctor 检查项 + 不做启动自动覆写)。

### 批次 4:多 agent 路由骨架(P2,暂缓,触发条件明确)

触发条件:用户实际提出"多个 AI 客户端同时驱动多个游戏实例"需求时再做。届时的设计输入:
- unity 的 fail-closed 三级路由(per-request override > per-agent 选择 > 默认)+ `AsyncLocalStorage` 贯穿(enhanced 的 MCP SDK 请求上下文是否有 `_meta` 通路需先探);
- agent→instance 显式绑定 + 项目消失要求重选(enhanced 因有 per-port secret,误连风险已被密码学挡住,显式绑定主要价值在**降低 auth 失败噪音**与多 agent 并发调度);
- 驱逐即收紧未知 agent 权限(agent-state LRU 语义)。

### 不做项(明确记录,防过度设计)

- **admission 准入记账**(256 未决+字节成本公式):单机单 agent 场景无此压力,做属冗余抽象。
- **启动兜底自动覆写项目内 bridge 脚本**:game-side autoload 场景重启前半新半旧,风险>收益(yanhuifair 能做靠 editor reload 原子性,不可比)。
- **MCP 商业化路径**(context7/blender-mcp 样本):与当前"免费+开源+安全"定位不符,仅作认知储备不落地。
