## 3. 真实性(4/5)

### 强项(实测,批3 声明逐项核实为真)

| 要素 | 证据 |
|---|---|
| HMAC 构造 TS/GD 对齐(key=secret/msg=challenge/UTF-8/hex 小写,跨端注释锁定) | `EditorConnection.ts:557` ↔ `websocket_server.gd:414-415`;bridge 同构 `bridge-client.ts:493-548` ↔ `mcp_bridge.gd:1015-1044` |
| 恒时比较(XOR 累积不短路+长度先等值) | `websocket_server.gd:669-675,654-663` |
| challenge 一次性(CSPRNG 128bit,消费/断开/旧 auth 成功三路清理) | `websocket_server.gd:405-407,360,419,443` |
| per-peer 指数锁定 + 无 secret 拒所有业务方法 | `websocket_server.gd:390-399,459-462` |
| instance API:HMAC+双向时间窗+nonce 64bit 持久化防重放+验证后记录(防污染池) | `src/core/instance-api-auth.ts:149-216,224-271` |
| 确认令牌 144bit 一次性+TTL+限速+out-of-band 架构 | `src/core/guard.ts:76-127`、`elicit.ts` |
| 输出 marker 窃取链三层拦截 | `gdscript-executor.ts:54,71,101` |

### 问题

- **P2【editor 侧 auth_proof 不校验响应语义,弱于 bridge 侧(不对称)】** `EditorConnection.ts:558-559`:`await this.request('auth_proof',{proof})` 对端回任何 result 即置 `authenticated=true`;对照 bridge 侧 `bridge-client.ts:552-557` 校验 `authenticated===false` 立即失败。半协议异构端(恒回空 result)可通过 editor 认证——但根因是 CR 防 secret 泄露、不防对端伪造(本机端口占先者天然可扮演服务端,文档已知残余面),此项属语义拉齐问题。
- **P2【明文 auth 通道保留+降级记忆不复位】**(与保密性 P2-1 同根)持 secret 方可以「旧 TS 客户端」身份通过认证,无协议版本绑定。
- **P3【锁定计数断开即清】** `websocket_server.gd:351-360`/`mcp_bridge.gd:319-328`:重连即清零,指数锁定失效;secret 190bit 暴力不可行,影响可忽略(GD 侧注释自认「仅减速带」)。
- **P3【challenge 无 TTL】** 从 auth_begin 挂到消费/断开;challenge 仅是 HMAC 输入,泄露无价值。
