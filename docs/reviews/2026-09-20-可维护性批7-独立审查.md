## 值得进 memory 的工程教训（审查者提 + 主会话补充）

1. **删除源文件前必须 grep 全仓静态消费点，含 `readSrc`/`fileContains` 类测试谓词**——`readSrc` 缺失返 `''` 的宽容设计让谓词静默假绿而非报错（B-1 根因，批2 埋、批7 审查发现，空转约 6 个批次）。
2. **`coverage/lcov-report/*.html` 是嵌入式历史源码快照，可当 `git show` 替代基准——但必须核对生成时间与目标基线 commit 的先后**，否则会把更早批次的改动误判到当前批（本次 B-1/N-3 归属误判的直接根因）。
3. **"机械搬迁"类 commit 的隐式连带必须进声明清单**——审查者对照声明打勾会漏声明外牵连面（final-review-must-check-repo-constraints-not-just-spec 又一例；本批实际无声明外连带，但审查机制把它当高概率风险核查是对的）。
4. **静态源码断言的引用形式要宽搜**：分段路径拼接（`'tools', 'script.ts'`）不含连续子串 `tools/script`，按子串 grep 会漏（本批 p6-batch P3-h 首轮全量测试才暴露）。
