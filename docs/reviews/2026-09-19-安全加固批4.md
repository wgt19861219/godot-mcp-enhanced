## 工程教训(进 memory)

1. 安全修复中"对齐"应向强语义对齐而非照抄弱侧,但必须实证兼容性——T1 升级为"非 true 即拒"的支撑是可实证的协议不变量(GD 端成功必回 true + auth_begin 已筛非 CR 端),而非假设。
2. 同一变换分散在多分支 return 路径时极易漏掉一两处(N-2 的 6 return 漏 2)——剥离/清洗类变换应收敛为单一出口或用测试枚举全部路径。
3. mock-fs 展开副本使真实 fs 写入静默无副作用——断言"文件真的落盘"的测试必须在无 fs-mock 的独立文件跑(godot-server-startup-audit.test.ts 先例)。
4. fire-and-forget 审计的路径求值发生在 promise 执行时——CLI 审计测试必须在该 describe 级别全局 stubEnv HOME,仅靠单用例局部 stub 会有跨用例竞态与真实 home 污染(configure.test.ts 教训)。
