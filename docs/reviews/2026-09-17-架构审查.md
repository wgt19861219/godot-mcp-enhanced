## 二、分级发现(三路汇总,High 级经主审逐条核实)

### High(4 条)

#### H-1 · `_coerce_math_value` 数学分量无类型守卫——I-C 崩溃类修复收口不彻底

`src/scripts/mcp_bridge.gd:1754-1764` 的 `_math_comp` 只判分量"非 null"不判类型,容器分量(如 `{"x": {}, "y": 2}`)进入 `float()` 触发 SCRIPT ERROR;`:1703-1750` 共 12 处 `Vector2(float(x), float(y))` 式裸转。仓库 2026-09-03 审查 I-C 已真机实证此崩溃类(`mcp_bridge.gd:2476-2477` 注释自证),批次 C 只修了 send_mouse_click/send_touch 顶层 x/y,分量层漏网;契约测试负向断言(`test/bridge-feedback-batch-c-contract.test.ts:44-56`)只扫这两个函数,给了"已收口"的错觉。headless 侧同款:`src/scripts/godot_operations.gd:97-144`,且 `_has_components`(`:58-84`)只数键不查类型;批次 B 的 B3-text 改为"Array 一律 fallback GD 链"后嵌套容器必然流经此路径。影响:bridge 侧一条毒消息→该请求 10s 超时+引擎错误刷屏;同步分发无异常隔离→响应静默变 `result: null`。三副本 DUPLICATE(mcp_bridge / godot_operations / editor command_helpers)同步债 +1。**主审核实:`:1754-1764` 代码属实**。
**修复方向**:`_math_comp` 返回前加 `is int or is float or (is String and is_valid_float)` 白名单(对齐 `_num` 先例),三副本同步;契约测试负向断言扩到全文件。

#### H-2 · `int/float(params.get(...))` 裸转 19 处——同款毒消息面遍布全命令族

`src/scripts/mcp_bridge.gd` 内 19 处裸转(行 1244/1352/1376/2651/2696/3025/3226/3329/3340/3536/3635/3638/3696/3724/3727 及 float 参数若干)。最危险的是 `_cmd_control_input_sequence` 的 `int(e["at_frame"])`(`:3696`)——深预检第一步只查 `has` 不查类型,`{"at_frame": null, "type": "key"}` 是合法 JSON 但直接崩;该命令走延迟通道(TS 侧 timeout 35-65s),一个毒事件烧掉整个 wall_budget 且无错误回显。另有 `float(ev["strength"])`(`:3749`)位于 `_process` 帧注入路径,崩溃可能中断当帧后续 pending 处理。**主审核实:`:3696` 代码属实,19 处计数 grep 实测**。
**修复方向**:抽 `_int_guarded(v, fallback)` 工具函数(整值/合法数字串放行,其余 fallback 或拒绝),clamp 前解析统一替换;深预检对 at_frame/settle_frames/wall_budget_ms/strength 补类型断言。

#### H-3 · O2 原样滚存:game-bridge.ts 模块顶层副作用装配,不受 close() 管辖

`src/tools/game-bridge.ts:110` 模块顶层 `setOnBridgeConnected(() => launchDashboardOnce())`——import 即执行,`GodotServer.close()` 无 `setOnBridgeConnected(null)` 对应项(对照 26-setter 配对表,这是 19 个注入型 setter 中**唯一失配**的一个)。缓解较 9-12 有改善:`src/dashboard/launcher.ts:38` 新增 `isWebGuiActive()` 守卫 + `GODOT_MCP_NO_DASHBOARD` 开关 + `_launched` 单次标志。危害低(回调闭包不持 server 实例引用)但"装配必须可在 close() 清理"的不变量存在结构性破口。**主审核实:`:110` 代码属实**。
**修复方向**:接线移入 GodotServer.run()(与 webGuiServer 同层装配),close() 对称置 null;模块顶层仅保留 re-export。

#### H-4 · dap 会话(TCP socket)完全不在 GodotServer.close() 清理链

`src/tools/dap.ts:118-119` 模块级 `_sessions`/`_breakpoints` Map 持有到 editor DAP server(127.0.0.1:6006)的 TCP socket;dap.ts 无导出的 closeAll(Grep 实测唯一导出函数是 `:265 handleTool`),`GodotServer.ts` 全文 grep dap 零命中=close() 无对应清理步骤。生产 stdio 路径被 `index.ts:141` 的 `process.exit(0)` 兜底不挂进程;但(a)close()"逐项配对清理"契约对第 46 号工具缺位;(b)嵌入式/测试场景 socket FD 泄漏 + `_breakpoints` 跨 server 实例残留(热重启后 list_breakpoints 可见幽灵断点)。**主审核实:两处 grep 均属实**。
**修复方向**:dap.ts 导出 `closeAllDapSessions()`(遍历 `_sessions` destroy socket + 清两 Map),GodotServer.close() 加 safeStep 调用。

### Medium(11 条)

#### M-1 · web-gui token 比较非常量时间(4 处)

`src/web-gui/server.ts:257/316/325/394` 用 `===`/`!==` 直接比较 token(主审 grep 核实 4 处)。浏览器攻击面被 Origin 严格相等关死,但 `origin === undefined` 放行(`:252`)意味着**非浏览器客户端不受限**——Windows 多用户机器上其他会话进程可连环回,定时侧信道成为 token 恢复的可行途径(拿到 token=面板全权:allowlist 内文本文件读写/停会话/拉起进程)。修复成本近乎零:`crypto.timingSafeEqual` 封装统一替换。

#### M-2 · 共享持久 token 无轮换/撤销,叠加包根入口页内嵌,泄露后永久有效

`src/web-gui/registry.ts:43-62` token.txt 永生(仅损坏时重生成)、所有实例共享、无过期无轮换命令;`portal.ts:115-120` 包根入口页内嵌该 token;`open.ts:67` CLI 打印全量 token 到 stdout。多实例语义:会话控制是进程本地的,但 projects.json 跨实例共享、files API 基于 allowlist——**任一实例面板可编辑 allowlist 内全部项目文件,token 一次泄露=所有实例失守**(cookie 域不分端口)。这是用户裁决接受的零门槛授权,但"永久性"是裁决时未必显式感知的属性。修复方向:`--rotate-token` 类命令(删 token.txt 即退化轮换,至少写文档)+ CLI 打码。

#### M-3 · `refreshProjectEntries` 向所有登记项目目录+CWD 无差别写入口页,穿透 READ_ONLY 语义

`src/web-gui/server.ts:825-836`(主审核实):start()(`:183`)、扫描完成(`:448`)、add 成功(`:493`)三时点把入口页写进**每一个**登记项目目录和 CWD。问题:(a)未逐项目征求同意的写入足迹;(b)用户项目的 .gitignore 不认识该文件名,untracked 污染易被 `git add .` 误提交(好在项目目录版不内嵌 token,误提交只泄露无害模板——子代理 A 证实含 token 版本的写入路径在代码上不存在,root 构造期固定);(c)READ_ONLY 拦截只盖 `:400` save 与 `:543` sessions/start,scan 路径的 refreshProjectEntries 无 READ_ONLY 判断——"读 ONLY"语义在"向项目目录写文件"维度被穿透。修复方向:READ_ONLY 时跳过;或 `GODOT_MCP_WEB_GUI_ENTRY=0` 开关。

#### M-4 · `/api/health` 无鉴权 + ACAO `*`,向任意远端网页开放本机指纹原语

`src/web-gui/server.ts:283-291`——任何公网网页的 JS 都能读取 `{ok, port, startedAt}`(存活确认+启动时刻)。信息面经刻意裁剪(无 pid/token),但 ACAO 可收紧为回显白名单 Origin(127.0.0.1/localhost 端口段)而非 `*`;`startedAt` 可移除(自愈只需 ok)。

#### M-5 · `game_bridge_uninstall` 无判活删光全部 secret——与 install 侧护栏哲学不对称

`src/tools/game-bridge.ts:694-702` 无条件删除 `.godot/` 下所有 `mcp_bridge_*.secret`,不调 `liveHeartbeatPortsFor`。同项目多实例在跑时,在跑实例的 secret 一并被删——进程内 auth 仍有效但 TS 侧重连即断,文案无提示。install 侧 `clean_stale_secrets` 都有"无新鲜心跳拒清"护栏(`:598-601`),uninstall 这个更强的破坏性操作反而没有。修复方向:删前查判活,非空时只删无心跳端口并点名保留项。

#### M-6 · O3 原样滚存:sync_state 快照仍无 project/port 维度

`src/tools/game-bridge.ts:142-161`——`SyncSnapshot` 无 projectPath/port 字段,跨项目同 label 静默覆盖,compare 两个不同项目的快照产出无意义 diff 零警告。本轮唯一实质加固是 truncated 截断防呆(`:994-999/1011-1019`)。修复方向:snapshot 记录 `getBridgeProjectDir()`+端口,compare 不一致加 `cross_project: true` 警告。

#### M-7 · O1 零收敛:哨兵延迟通道 5 变体+共享单槽 `_last_step_request_id`

`src/scripts/mcp_bridge.gd:97-103/77/1189-1211/995-1054`——每新增延迟命令仍需动 4 处(handler 哨兵键→识别分支→`_pending_*` 变量→消费分支);`_last_step_request_id`(`:77`)被 3 条哨兵通道共享,靠"设置与消费同调用栈"的隐式约束保证正确,未来某 handler 在设置哨兵后加 await 即踩空。修复方向:收敛单例 `_deferred_ctx` 槽(键含 kind/id/payload),消费端按 kind 分派。

#### M-8 · 版本指纹接线面窄——非 ping 路径零提示

GD 侧 registry 回传 `bridgeVersion`(`mcp_bridge.gd:878`)但 TS 侧 `resolveBridgePort` 不消费;版本比对只在 `game_query ping` 直连路径(`game-bridge.ts:807-810`)。agent 直接调 `send_drag` 在旧版 GD 上拿 -32601 时看不到版本信息(GD 侧文案有重装指引兜底)。修复方向:`sendToBridge` 收 -32601 时自动补 ping 比对,错误内嵌 versionWarning。

#### M-9 · ctx.functionProfiler 生命周期依赖间接事件链,close() 无直接清理

profiling 模式 `run_project` 创建的 `DebuggerProfiler`(内含未 unref 的 `net.Server`,`src/core/function-profiler.ts:333-348`)不被 close() 直接关闭,依赖 close()→killAllRunSessions→proc 'close' 事件→runtime.ts:285-291 handler 关闭;killProcess 有 5 秒超时兜底路径(此时 profiler server 可能仍监听)。嵌入式使用事件循环可被吊住。修复方向:close() 补一步直关,或 net.Server 加 unref。

#### M-10 · clearAllInflight 在 close() 首步,与并发 in-flight 工具调用存在重写竞态

`GodotServer.ts:742` 首步清 inflight 文件;close 进行中(60s qa cancel 等待窗内)的并发工具调用 `markInflight`(`ToolDispatcher.ts:270`)会重建该文件,进程退出后残留→下次启动 `reportOrphanedInflight()`(`:130`)把 graceful close 误报为"非正常退出死亡时报丧"。诊断噪音不损坏功能。修复方向:close() 末尾再清一次,或 inflight 加 `_shuttingDown` 短路。

#### M-11 · inflight.ts 每次工具调用 2 次同步文件 I/O

`src/core/inflight.ts:57-77` markInflight/clearInflight 每次 readFileSync+writeFileSync 全文——hot path 新引入同步点,与既有"async fs 避免阻塞事件循环"原则(C-02)相悖。文件几百字节单次微秒级,实际影响低。修复方向:内存副本+防抖写盘。
