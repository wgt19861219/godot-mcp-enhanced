## 工程教训（已登 memory）

- URL 进 Windows bat 必须 `%`→`%%` 双写；平行 `if exist` 探测链须统一 `if not defined VAR` 前缀，否则后位命中覆盖首命中优先级。
- cmd 按 ANSI 代码页解析 bat：模板纯 ASCII + 数据先 percent-encode 再进模板，是 bat 生成器通用范式。
- 新增编码/校验函数后要 grep 同语义既有内联实现一并收口（buildFileUrl 初版漏掉 open.ts 的 portalUrl 手拼）。
- `start` 拉起的子进程继承父 stdio 管道句柄：node execFile(cmd /c bat) 会因管道不 EOF 挂起——验证脚本须 `stdio: 'ignore'`。

## 追加批：网络异常误报修复（同日，用户真机反馈驱动）

用户反馈「网络异常,扫描请求未送达」。定位：文案出自面板前端 scan 按钮的 fetch catch 兜底（html.ts），根因是 **server 鉴权 401 只写状态码无响应体（`writeHead(401).end()`），前端无条件 `r.json()` parse('') reject 落 catch**，把「鉴权失效」伪装成「网络异常」。触发链：自愈迁移后 sessionStorage per-origin 丢失 + cookie 失效 → 前端 token 变量为空 → 401 → 误报。

修复：新增前端 `safeBody()`（text 先行，空体/非 JSON → body:null），六处 fetch（scan/add/files 目录/file 文本/save/hex）统一接入；各失败分支补 401 文案「鉴权失效,请从 面板入口.html 重新进入」（刷新不闭环——query 已被 replaceState 清、sessionStorage 迁移即丢；回入口页带 token 跳转才闭环）；顺带修 add 响应打包漏 status（403/404 分支从不命中）；hex 旧 401 哨兵升级 safeBody（403 空体同覆盖）。

验证：真机端到端复现——chrome-devtools 打开新 build 面板，evaluate 模拟鉴权失效态（空 token + credentials:'omit'）：同一 401 空体响应，修复前 `r.json()` reject(SyntaxError) 完整复现用户文案，修复后 safeBody 产出 `{ok:false,status:401,body:null}` → 「扫描失败: 鉴权失效,请从 面板入口.html 重新进入」；正向路径真实点击扫描按钮 → JSON 正确解析、业务错误如实展示。门禁：lint 0 错 / build 0 错 / 全量 vitest 449 文件 6644 用例通过。

追加教训（已登 memory）：空 body 响应上先 `r.json()` 必 reject——server 侧"写头即 end"的轻量错误响应与前端 JSON 解析约定组合出的静默误报面；同款兜底文案散布多处时，一处修复必须 grep 全部同模式收口（hex 处先前修过 401 却没扫其余六处）。
