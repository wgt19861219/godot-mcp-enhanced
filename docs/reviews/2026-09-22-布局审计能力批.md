## 7.5 值得进 memory 的工程教训

1. flaky 测试改集合断言时，"为什么两条码都合法"的机制注释必须沿代码 reject→catch 链路**实测归因**——凭直觉写"超时走显式失败码"会产出与实现相反的解释（connect timeout 实际与 socket error 同走 catch 兜底 `DAP_ERROR`，见 `dap.ts:636`/`:331`）。
2. 测试改名的处置要做"标题每一项 ↔ 断言"双向核对，不是改完名即闭环（import-integrity 标题"git 层为 null"至今无断言）。
