## 五、过程中踩的坑（值得进 memory）

1. **方案文档的 API 名必须实测**：方案自标"ink API 验证是唯一风险点"风险意识对，但写进文档的 `Font.get_glyph_size/get_glyph_index` 照抄会立刻撞墙——审查阶段 ClassDB 证伪 + 实现阶段又连环发现 `get_primary_interface` 更名与 `Vector2i` 签名（`--script` 探针 Parse Error 是最快证伪途径）。
2. **`check:gdscript`（--import）0 errors ≠ 脚本 parse 通过**：`--import` 不 load 未被引用的 autoload 脚本；p7 探针（`load + new`）才是更深的验证层。本批两个 Parse Error 均由探针抓住、check:gdscript 漏报（AGENTS.md §6 教训的再实证）。
3. **fixture 拷贝时机**：`test/fixtures/gdscript-check/src/scripts/mcp_bridge.gd` 由 vitest global-setup 填充，`npm run build` 不碰它——手动探针验证前必须先 `cp` 同步，否则验证的是旧代码（假阴/假阳都可能）。
4. **stash 实验 + `&&` 链 + git status 偶发 warning**：复合命令里 `git stash pop >/dev/null && git status` 的 status 因 "could not open directory" warning 退出非零，造成"pop 失败"误判——恢复性操作后用 `git diff stash@{0}` 直接对账内容而非信任链路退出码。
5. **测试环境 `GODOT_MCP_UNRESTRICTED=true`**（`test/setup.js:6`）会让白名单拒绝用例假阴——用 `vi.stubEnv` 用例内临时关闭再还原（安全加固批6 同款坑再实证）。
