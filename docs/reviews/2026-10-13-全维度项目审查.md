## 四、安全体系 — 声明与实现一致，3 Medium 结构性缺口

五大护城河逐项实测均真实且经历史加固（详细证据链见安全子代理报告，此处摘要）：

- **路径白名单** ✓：deny-by-default 精确（未配置时回退限 cwd，`src/core/path-utils.ts:273-285`）；junction 双 realpath（C-1）；UNC/设备名/drive-relative/段级 `..` 全拒。
- **GDScript 沙箱** ✓：三层纵深（action-gate 默认拒 → kill switch → 三阶段扫描），危险模式约 30 条含网络回连/marker 窃取链；沙箱关闭需双开关（`src/core/sandbox-scanner.ts:463-469`）。
- **确认令牌** ✓：两轮 elicitInput out-of-band（`src/core/ToolDispatcher.ts:498-540`），TTL+限流+LRU，AI 无法经 tools/call 通道伪造。
- **输出标记** ✓：122-bit 熵 marker + untrusted 信封。
- **web-gui/daemon HTTP 面** ✓：恒 127.0.0.1；token 192-bit 恒定时间比较；CSP sha256 精确放行；daemon /mcp 有 Host 校验（防 DNS rebinding）+ Bearer 双闸。
- **密钥卫生** ✓：全仓无硬编码凭据；token/secret 落盘均 0o600+icacls+symlink 拒写；icacls 用户名白名单防 ACL 注入。
- **命令注入** ✓：spawn 全数组形式无 shell:true；唯一 PowerShell 插值点有标准转义。

### Medium 缺口（建议排期处理）

- **M-1 路径校验覆盖面靠纪律**（置信 85）：`validatePathArgs` 仅强制根级 `project_path`/`search_dir`（`src/core/ToolDispatcher.ts:822-836`），其余路径参数由各工具自行调 `resolveWithinRoot`。当前抽查无存量绕过，但新增工具漏接即绕过根限制。建议：schema 层声明式标记路径参数，或加静态扫描断言「接收路径参数的工具必须 import resolveWithinRoot」。
- **M-2 Godot 二进制白名单 back-compat 放行**（置信 85）：`src/core/godot-finder.ts:118` 白名单与 godot-paths.json 皆未配置时（新装默认态）放行任何候选路径，仅靠 `--version` 签名校验兜底——伪造签名脚本可绕（注释自认）。与项目路径白名单的 deny-by-default 哲学不一致。建议默认收紧为「仅登记路径+env 显式值可用」。
- **M-3 面板 token 同用户进程可读 + settings API 可热改白名单**（置信 82，威胁模型内取舍）：token 落 `~/.godot-mcp/web-gui/token.txt`（0o600 仅防他用户）→ 同 UID 进程可凭 token 热改 `allowedProjectPaths`。未越出「本地单用户」声明边界，但 web-gui 默认开启（`src/GodotServer.ts:723,737`）使该面常态存在。建议文档显式披露 + 可选显式开启模式。

### Low

- **L-1** web-gui 默认开启（`GODOT_MCP_WEB_GUI !== '0'` 即启动），默认扩大 attack surface（若采纳 M-3 建议则一并解决）。

**诚实边界声明评估**：项目多处源码（非仅 README）声明「防误操作层非安全边界」并逐条列出已知绕过形态——**该声明准确且与实现一致**。

1. **性能/超时绊线在高负载本机会假红**——并行跑重审查任务时的测试失败必须先单独复跑定性再动手修（本批 4 个失败复跑 19/19 全过，避免了一次虚假回归修复）。
2. **`expect(true).toBe(true)` 形态是弱断言门禁的检测盲区**——WEAK_RE 只盯 `toBeTruthy/toBeDefined/not.toBeNull`，空断言需人工审查捕获。
3. **「两套信任边界并存」是有意设计时必须在文档声明**（vault vs ALLOWED_PROJECT_PATHS），否则每次安全审查都会被重新质疑一遍。
