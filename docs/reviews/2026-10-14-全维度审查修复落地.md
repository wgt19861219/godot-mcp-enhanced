## 工程教训(值得进 memory)

1. **双重遗漏的结构性原因(C1)**:v0.18 工具吸收只搬 handler 委托不搬 schema 声明,而三层自检(直调 handler 的测试/按文件归属的 SSOT/自洽的 matrix)各自"正确地"漏过——跨文件委托形态必须配跨文件对账机制(SSOT-DELEGATE 标记是本次落地)。
2. **CSP sha256 约束下的前端参数化(M6)**:内联脚本字面量不能在发送期替换(hash 失配被自家 CSP 拦),参数化要走 script 外的 meta 通道;且 GUI_STRINGS 的内联字典序列化使"加 i18n 键"级联 hash 轮换——hash 锚测试的独立重算双通道设计正确捕获了两次级联。
3. **i18n 键复用的 API 契约陷阱(M4)**:复用语义近似的现有键(err.notAllowed)会悄悄改变 en 响应文本,破坏对错误文本的既有匹配——API 契约点应新建 en 与原文逐字一致的独立键。
4. **审计字段与响应文案的分界(M4)**:响应体 error 走用户语言,审计 details.error 保持英文标识符(机器消费 + 源码契约断言依赖)——批量替换脚本须区分这两个面(本批曾误伤 1 处,靠源码契约测试抓回)。
