## 2. 分发/打包(最高优先级)

### A1 [HIGH] npm 包缺 `docs/api/extension_api.json`,`docs` 工具在发布包中必然抛错
- **证据链**:
  - `package.json` 的 `files` 只含 `"docs/tools/**/*.md"`(无 `docs/api`);
  - `npm pack --dry-run` 实际清单中 docs 下**只有 46 个 tools/*.md**,无 `docs/api/extension_api.json`(也无 `data/godot-classes.json`);
  - `src/godot-docs.ts:212` 运行时用 `join(dirname(fileURLToPath(import.meta.url)), '..','docs','api','extension_api.json')` 解析,即安装包内 `<pkg>/docs/api/extension_api.json`;
  - `src/godot-docs.ts:213-221` 文件不存在则 **throw**;`src/tools/docs.ts:6-11` 直接消费这些导出且 handler 无 try/catch(`docs.ts:93-196`);
  - 仓库根无 `.npmignore`(不存在),无法"反转"该缺失。
- **影响**:`docs` 工具在默认 `basic` profile 的 tools/list 中可见(实测 26 个里含 docs),用户调用即得 "Godot docs database not found"。属 46 工具之一的**发布态功能不可用**。
- **修复建议**:`files` 增加 `"docs/api/extension_api.json"`;或把该数据搬进 `build/` 并在 build 脚本拷贝;并加一条打包内容守护测试(见 A2)。

- 现有 `check:*` 全部针对源码/契约/文档,**没有任何测试断言 `npm pack` 产物包含运行时必需文件**。A1 因此长期隐身。

### D1 [MEDIUM] READ_ONLY 下 `/api/settings/verify` 仍可 spawn 任意本地可执行文件

### D2 [MEDIUM] 服务端未拦跨实例 daemon 硬重启

### D3 [MEDIUM] `controlledRestart` 失败包容面缺口
