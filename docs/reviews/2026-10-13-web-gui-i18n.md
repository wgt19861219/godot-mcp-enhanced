## 值得进 memory 的工程教训

1. **机械重命名必须 grep 旧名全部残留**:`t→ts2` 改名漏 1 处引用即运行时 ReferenceError 回归——重命名后以 `\b旧名\b` 全文 grep 收尾,而非依赖肉眼。
2. **字符串断言 + vm.Script 编译对"未定义变量"零防护**:本项目前端测试策略(契约锚断言+语法编译)抓不住标识符解析类运行时错误;大幅改动内联脚本的批次,应用执行级冒烟(vm+DOM stub 派发 SSE 帧)补渲染路径——B-1 同时穿透 7265 用例与真机端到端两道防线的根因。
3. **端到端验收清单偏向本批新功能面**:被改函数的存量数据路径(timeSeries 非空)不在清单内——改动波及的既有功能路径应进验收清单。
4. **i18n 键引用的测试门禁要按"命名空间字面量"扫描而非只扫 t() 调用形态**:对象形态/三元分支等引用形态逃逸 t() 正则,按 KEY_NS 前缀匹配所有单引号键字面量才是完备防线(Nit-3 对策)。
