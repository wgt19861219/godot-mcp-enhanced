## 值得进 memory 的工程教训

1. (methodology)方案中「二选一,实现时定」类开放条款最易被静默跳过——执行者两边都没选也无人发现;审查方案落地时应 grep 方案全文的「二选一/可选/实现时定」逐条核对是否被「定」掉(本次 I-1 即此模式)。
2. (testing)防回归用例必须构造能暴露差异的最小场景:在「有 bg」前置下断言 draw_center 不触发是恒真弱断言,测不出 hasBorderish 判定逻辑的回归。
3. (methodology)无命令执行环境下 git 状态可静态还原:`.git/HEAD` + `refs/heads/*` + `COMMIT_EDITMSG` 三件即可判断「已提交/未提交」;双副本一致性可用「行偏移恒定性 + 跨段独特字样多点 grep」作 STRICT 脚本的高置信旁证。
