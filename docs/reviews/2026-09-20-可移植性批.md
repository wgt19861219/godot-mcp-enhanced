## Important Issues(3,全处置)

### Important-1(置信度 85):enabled 清理只匹配裸名,清不掉 Godot 4 编辑器真实写入形式

- **位置**:`src/cli/uninstall.ts` removeFromEnabledLine
- **问题**:本仓库无任何代码写 `enabled=` 行(全仓 grep 核实,install-plugin.js 只拷文件)——真实用户项目中该行只能来自用户在 Godot 编辑器启用插件,而 Godot 4 写入的是 `enabled=PackedStringArray("res://addons/godot_mcp_server/plugin.cfg")`(完整 res:// 路径),非裸名 `"godot_mcp_server"`。只匹配裸名 → enabled 行不改写 → addon 删除后残留死引用,下次打开项目 Godot 报插件加载失败。
- **测试为何绿**:fixture 用裸名,与引擎真实输出不一致——测试自洽掩盖缺陷。
- **处置**:双形式匹配(`"godot_mcp_server"` + `"res://addons/godot_mcp_server/plugin.cfg"`);补 res:// 形式用例 + 空数组分支用例(Nit-5 顺带)。

### Important-2(置信度 100):审计 caller 硬编码,uninstall 复用后归因错标

- **位置**:`src/cli/audit-helper.ts` auditCliProjectWrite 的 `caller: 'cli:init'` 硬编码 + uninstall.ts 复用
- **问题**:uninstall 的项目写面审计条目变成 `caller=cli:init, action=uninstall_addon`——抗抵赖审计(批4-T9 设计目标)归因字段错误。
- **处置**:caller 提为参数(默认 `'cli:init'` 保存量兼容),uninstall 传 `'cli:uninstall'`。

### Important-3(置信度 85):Phase 1 无确认门,与文件头注释矛盾

- **位置**:`src/cli/uninstall.ts` 文件头注释("TTY 逐阶段 confirmYesNo")vs Phase 1 实现
- **问题**:TTY 用户运行 uninstall(无 --yes),Phase 1 直接改写最多 15 个客户端配置文件——其中 antigravity/codex/claude-desktop 等是 global scope(用户全局配置),不经任何确认。
- **处置**:Phase 1 前补 confirm(含 global scope 提示文案);dry-run/--yes 下短路 true 零成本。

## 实现过程中的额外发现(非审查产出)

- **defects 基线拦截实例**:uninstall.ts 首版在模块级声明 `const __pkgRoot`(对齐直觉上的 doctor.ts 模式),命中 `module-level-mutable-state` 谓词(`/^(let|const) _/` 保守计数)致 85→86 超基线;doctor.ts 的同名变量在**函数内**故不计数。移入函数内解决——比 bump 基线干净。
- **vitest 4.1 模块 mock 构造器陷阱**:`vi.mock` 工厂的 `vi.fn().mockImplementation(() => obj)` 箭头 impl,被测代码 `new InstanceManager()` 时 vitest 把箭头函数当构造器调用直接 TypeError("not a constructor"),被 findAliveInstances 的 try/catch 吞成"无在跑实例"假象。工厂 impl 必须普通 `function`;另直接 patch 工厂导出的 mock fn 不可靠,用 `vi.hoisted` 共享状态驱动。已固化在测试注释。

## 值得进 memory 的工程教训

1. **fixture 格式与引擎真实输出漂移会制造"测试自洽的假覆盖"**——断言"清理引擎生成内容"的纯函数,fixture 必须先用真引擎生成一次再固化,或至少双形式覆盖(本次:裸名 vs Godot 4 的 res:// 路径形式)。
2. **审计 helper 复用要看隐式归因字段**——caller/action 一个传参一个硬编码,第二个调用方接入即归因错标;审计类 helper 的归因字段应全参数化。
3. **破坏性命令的"逐阶段确认"要在评审时逐阶段数**——注释声明与各 Phase 实现逐一对账,这类注释-实现漂移在多阶段 CLI 命令中最易发生。
4. **vitest 4.1:vi.mock 工厂的 mock impl 用箭头函数 + 被测方 new → TypeError 被吞**——模块 mock 工厂 impl 必须普通 function;场景化覆盖用 vi.hoisted 状态而非 patch 导出。
