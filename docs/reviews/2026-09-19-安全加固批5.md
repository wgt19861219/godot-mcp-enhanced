## 工程教训(进 memory)

1. **语义升级的隐藏耦合面是"解释性文案"**:函数名 grep 能找到数据消费方,但自然语言复述旧语义的 hints 文案不引用函数名——grep 漏掉,形成"检测能力升级了、检测报告却把人引向错误结论"的断点。今后语义变更应同时 grep 字段名字符串(如 diverged)。
2. **"由既有用例覆盖"的声明必须 grep 证实**:本批方案声称 parseErrors 有回归覆盖,实测零断言——声明性测试是审查必须戳破的(同 final-review-must-check-repo-constraints 教训同构)。
3. **认证协议 mock 测试的"自证"范式**:mock 异形对端测失败语义时,必须配 happy path 用例证明 mock 协议与真实协议一致(读 GD 源码核对,非凭记忆)——否则失败用例可能只是在测"mock 协议写错了"。test/bridge-auth-proof.test.ts 的 ③+①② 结构是可复制样本。
4. **固定端口的单元测试与 e2e 测试共享端口号时,门控条件(E2E_EDITOR)就是唯一隔离层**——门控放宽即静默冲突,动态端口(listen(0))才是结构性解。
